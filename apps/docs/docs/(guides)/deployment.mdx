Web and docs ship to Vercel through GitHub Actions; `infra/` holds an Alchemy stack with local state and no resources, so this page covers what deploys ship and what the first infra deploy still needs.

## How deploys ship

- Staging :: every push to `main` runs `.github/workflows/staging.yml`, one preview deploy per app — web and docs on separate Vercel projects
- Production :: manual `workflow_dispatch` on `.github/workflows/production.yml`, builds then promotes with `--prod`
- Secrets :: Infisical OIDC per environment; `VERCEL_WEB_PROJECT_ID` and `VERCEL_DOCS_PROJECT_ID` select the project

## What builds today

- Web :: `pnpm web:build`, Next plus the Varlock env plugin plus the Sentry plugin, bundle analyzer when `ANALYZE=true`
- Docs :: `pnpm docs:build` through Blume
- Both :: from the root through Turbo, exact pins plus the committed lockfile

```sh
pnpm web:build
pnpm docs:build
```

## Infra state

- Stack :: `infra/alchemy.run.ts`, named `vazen`, empty provider layer, `Alchemy.localState()`
- Scripts :: `plan` previews, `deploy` ships, `destroy` tears down, local state only until the first provider lands

```sh
pnpm --filter infra plan
pnpm --filter infra deploy
pnpm --filter infra destroy
```

## Before the first deploy

- Secrets ready :: Infisical staging and production plus each package `.env.schema`, validated by `pnpm env:codegen`
- Vercel ready :: `web` and `docs` projects exist with root directories set, plus `VERCEL_WEB_PROJECT_ID` and `VERCEL_DOCS_PROJECT_ID` secrets
- Open :: infra provider choice, demo seed strategy
- Previews :: auth allows `*.vercel.app` alongside the local `.id` hostname and `web.vazen.dev`
